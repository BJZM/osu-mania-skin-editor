# startup-actions

**一句话职责：** 管理启动阶段的谱面、皮肤选择顺序，提供画布中央操作面板与拖拽文件分流，并在谱面与皮肤来源同时就绪前阻止编辑与播放。

## 接口

- `initStartupActionsUI()`：绑定启动面板、拖拽区和“从默认皮肤开始”按钮。
- `isStartupSkinReady()`：当前是否已经选择默认皮肤或成功导入皮肤。
- `isStartupBeatmapReady()`：当前是否已经成功导入谱面。
- `isStartupWorkspaceReady()`：谱面与皮肤来源是否都已就绪。
- `isSkinEditingWorkspaceReady()`：当前是否允许详细设置与贴图编辑器读写皮肤参数和贴图；必须同时满足谱面与皮肤来源条件。
- `syncSkinEditingAvailabilityUI()`：根据缺失项切换两个编辑窗口的“请导入谱面 / 请导入皮肤”空状态与对应导入入口。
- `markStartupBeatmapReady(fileName)`：记录谱面已导入，并刷新启动面板与播放器状态。
- `markStartupSkinReady(sourceLabel)`：记录皮肤来源已选定，关闭启动面板，并恢复处于打开状态的编辑器内容。
- `shouldDeferSkinRendering()`：谱面已导入但皮肤未选定时返回 `true`。
- `canPlayWithStartupSelection()`：谱面已成功导入且皮肤来源已选定时返回 `true`。
- `syncStartupPlayerControls()`：按启动流程状态统一同步播放按钮和进度条禁用状态。

## 输入

- 启动面板按钮、文件输入和画布上的拖拽事件。
- `.osk`、`.osz`、`.osu` 与 `.zip` 文件；`.zip` 通过内容中的 `.osu` 条目判断为谱面包，否则按皮肤包处理。
- **前置条件**：现有文件输入和导入处理器已加载；`JSZip` 可用于 `.zip` 内容判定。

## 输出

- 更新启动面板可见状态、按钮描述、播放器可用状态与编辑器可用状态。
- **后置条件**：谱面与皮肤来源都就绪前不能播放，启动面板保持可见并显示还缺少的导入项。
- **后置条件**：任一前置项缺失时，详细设置的 Mania / 字体 / 基础设置 / skin.ini 文本页和贴图编辑器的选择 / 创建 / 编辑页均只显示对应导入提示。

## 依赖模块

- 现有谱面导入与皮肤导入处理器：通过向 `oszInput` / `oskInput` 注入文件并派发 `change` 事件复用解析流程。
- `default-skin-workspace`：用户选择“从默认皮肤开始”后激活。
- `global-skin-state`：读取当前谱面与皮肤工作区状态。

## 副作用 / 外部资源

- 读写 DOM 面板、文件输入和播放器控件状态。
- 读取拖入文件内容以判断模糊的 `.zip` 类型。
- 不发起网络请求，不上传文件。

## 非功能

- 拖拽事件只处理第一个文件，并阻止浏览器默认打开文件。
- `.zip` 类型判定只读取压缩包目录，不解析完整谱面或皮肤。
- 状态更新幂等，重复导入不会重复创建启动面板。

## 深度评估

- 调用方只看到“是否可渲染 / 是否可播放 / 标记完成”这几个状态，文件分流、拖拽生命周期和控件同步均隐藏在模块内。
- 删除该模块后，渲染、播放器、谱面导入和皮肤导入都要各自维护启动顺序约束，复杂度会散到至少四处，因此保留。
