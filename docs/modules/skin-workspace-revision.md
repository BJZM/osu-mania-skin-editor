# skin-workspace-revision

**一句话职责：** 记住当前皮肤工作区状态编号，并判断它是否已经成功导出。

## 接口

- `reset()`：把当前状态和已导出状态都回到导入基线 `0`。
- `advance()`：记一次新的已提交操作，返回新的当前状态编号。
- `adopt(snapshot)`：撤回、重做或回滚后，把当前状态编号恢复成快照上的 `revisionId`。
- `markExported()`：把最近一次成功导出对齐到当前状态编号。
- `hasUnexportedOperations()`：当前状态编号与已导出编号不同时返回 `true`。
- `currentId()` / `exportedId()`：读取两个编号。
- 不变量：同一次连续操作只 `advance()` 一次；撤回后若回到已导出编号，不再视为未导出。
- 错误模式：快照没有整数 `revisionId` 时，`adopt()` 保持当前编号不变。

## 输入

- 历史快照对象，可带整数 `revisionId`。
- **前置条件**：皮肤导入、默认皮肤重置或初始快照保存时先 `reset()`。新操作进入撤回栈时再 `advance()`。

## 输出

- 布尔值或状态编号。
- **后置条件**：成功导出后 `hasUnexportedOperations()` 为 `false`，直到下一次 `advance()` 或 `adopt()` 离开该编号。

## 依赖模块

- 无

## 副作用 / 外部资源

- 只修改页面内的模块状态，不写文件、不访问网络。

## 非功能

- 调用同步完成。
- 编号只增不复用；撤回恢复的是快照上已有编号。
- 重复 `markExported()` 幂等。

## 深度评估

- 接口只暴露编号对齐，快照如何克隆仍留在历史模块。
- 删掉后，导出是否覆盖当前操作会散落到撤回、重做、导出和关闭提示里。
- 原子模块：不依赖其它项目模块，可被历史记录和导出分别调用。
