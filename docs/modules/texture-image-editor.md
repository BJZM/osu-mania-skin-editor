# texture-image-editor

**一句话职责：** 组合贴图选择、纯色形状创建、可选像素边界描边、裁剪扩边、缩放、颜色调整、KeyImage 分状态参数同步、历史记录、长条合成与保存流程。

## 接口

- `initTextureImageEditorUI()`：初始化编辑器 DOM、标签页和所有交互。
- `textureImageEditorUi.open()` / `close()`：打开或关闭编辑器。
- `textureImageEditorUi.refreshAfterSkinImport()`：皮肤资源整体替换后清空旧编辑会话，并按新皮肤重建当前标签或选择页。
- `textureImageEditorUi.focusParams(paramKeys)`：打开贴图选择页，展开目标分类、滚动并高亮一个或多个参数卡片。
- `textureImageEditorUi.selectByParamKey(paramKey)`：按参数键打开贴图编辑标签。
- `textureImageEditorUi.syncExternalFrames(target, frames)`：同步外部上传或动画编辑产生的新帧。
- `textureImageEditorUi.getState()`：返回当前标签、输出尺寸、预览、历史可用状态以及创建器状态。
- `textureImageEditorUi.openCreator()`：每次调用创建独立、可关闭的“创建贴图”标签；同一路径的生成设置会复用已有编辑标签，标签切换时各草稿互不覆盖。
- `textureImageEditorUi.openLibraryEditor(pathOrSource)`：按“全部贴图”中的实际资源路径打开通用编辑，不要求该贴图绑定 `skin.ini` 参数。
- “菜单”中的贴图参数若解析到自建贴图，其“编辑”按钮悬停后展开 `通用编辑 / 生成设置`；普通贴图仍直接进入通用编辑。
- 贴图编辑窗口固定包含不可关闭的“菜单”和“全部贴图”标签；标签栏右侧的加号是唯一新建入口，标签空间不足时先自动缩窄，到达最小宽度后再横向滚动。
- 连续点击加号可并行准备多张贴图；每张草稿分别保存名称、尺寸、颜色、描边与形状参数，确认一张后优先切换到下一张未完成草稿。
- 保存成功后更新皮肤贴图仓库、参数查找与 `userReplacedTextures`；关闭时按标签恢复预览快照。
- 除 `KeyImage` 外，贴图保存默认直接覆盖当前实际资源路径，不自动生成新贴图名或额外图片。
- 若当前贴图还被其他轨道引用，保存前会询问“同步修改原图”或“独立创建副本”；只有用户明确选择独立创建副本时，才创建第二张图并把当前轨道切换到副本。
- `KeyImage` 主保存只处理当前轨道，并同步 `KeyImage` 与 `KeyImageD` 的裁剪和图片变换参数；保存菜单提供全部轨道，以及仅更新当前状态的高级方式。
- `KeyImage` 与 `KeyImageD` 始终使用各自原始帧生成独立贴图，即使二者原本引用同一文件也不会共享新产物；同状态、同引用轨道的分组规则保持不变。
- “设为空白”只生成 1×1 全透明编辑预览，计入撤销/重做并标记未保存；点击“保存到皮肤”后才写入替换资源。
- 已保存的 1×1 全透明贴图仍作为可编辑目标重新打开，不会因尺寸或透明占位标记禁用“编辑”。

## 输入

- 现有皮肤仓库、`skin.ini` 参数 schema、当前键数与活动皮肤快照。
- 用户输入的尺寸、填充颜色/透明度、形状、描边颜色/宽度/透明度、裁剪、拉伸与 RGB 参数。
- 通用编辑目标既可以是 `skin.ini` 参数，也可以是“全部贴图”中的具体资源路径；路径目标保存时只更新图片资源，不改参数查找映射。
- 自建贴图把生成参数和通用编辑参数分开保存；重新应用时先生成本体，再重放通用编辑，贴图仓库和导出中始终只有最终效果图。
- 创建贴图目标选择器以“替换：”呈现；逐轨贴图沿用详细设置的分组与名称，支持独立折叠，未分组的贴图保持直接排列。
- 圆角矩形与菱形共用可调圆角半径，拖动条与数值框同步且上限随形状尺寸变化；箭头形状额外接受粗细与圆角程度参数，并在创建草稿中保留。
- 描边默认关闭，启用后沿填充像素边界向内占据指定像素宽度，并从填充层中扣除描边区域；描边透明度与填充透明度分别保存和传递给形状工厂。
- **前置条件**：已经导入皮肤或选择从默认皮肤开始；皮肤资源和参数 schema 已初始化；目标贴图参数至少存在一个可解析的 base 名。

## 输出

- 持久化后的单帧或多帧贴图、参数查找更新与编辑器状态。
- 路径目标保存后刷新对应贴图资源、创建参数与编辑配方，并允许再次打开时恢复裁剪、拉伸和 RGB 设置。
- 默认覆盖原图后，当前参数继续保持原路径；选择独立创建副本后，只有当前轨道参数切换到新路径，并继续在新图上编辑。
- KeyImage 应用按“状态 + 原始贴图引用”分组生成独立资源，并把各目标自己的 RGB 参数保留在编辑配方中。
- **后置条件**：保存后的贴图可从现有渲染解析器读取；关闭某个创建标签只移除该草稿，其他创建草稿保持不变；取消或关闭未保存贴图标签时恢复原预览。
- **空状态后置条件**：未选择皮肤来源时，窗口仍可打开，但选择、创建和编辑视图都不会渲染可操作内容，只显示导入皮肤或从默认皮肤开始的提示。

## 依赖模块

- `texture-solid-shape-factory`：生成创建流程的初始纯色形状与可选像素边界描边 canvas。
- `texture-rgb-adjustment`：对输出帧应用通道调整。
- `texture-library-tab`：管理常驻贴图库标签、复制命名和删除确认。

## 副作用 / 外部资源

- 读写皮肤图片索引与 `userReplacedTextures`。
- 生成 canvas、PNG Blob 与对象 URL。
- 修改 DOM 标签、按钮、预览和提示状态。

## 非功能

- 单次输出受最大单边尺寸与总像素数量限制。
- 编辑历史最多保留固定数量的局部操作。
- 创建器实时预览使用缩小画布，避免按目标大尺寸反复分配完整位图。

## 深度评估

- 对调用方暴露的是编辑会话和保存结果，内部统一隐藏参数解析、标签生命周期、历史与持久化细节。
- 纯色形状创建复用现有编辑会话，而不是另建第二套保存流程。
- 删除该复合模块后，预览、历史、长条合成与导出约束会散到多个 UI 调用方，因此保留。
